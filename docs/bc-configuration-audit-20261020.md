# B/C 数据一致性与商家配置检查

## 检查范围与结论

检查日期：2026-10-20。覆盖模型/DTO、B端表单/API、C端首页/详情/购物车/结算/订单/助手、缓存失效及角色权限。不是只看接口存在：新增测试执行“商家修改 → 买家读取 → 报价/下单 → 历史快照”链路。

既有商品、SKU、标签、轮播、栏目、优惠券主要数据共用数据库；原实现并非所有内容均可配置，检查发现并修复下面的真实缺口。业务正确性与商家可配置性要分别判断，不能将“B/C都返回相同错误数据”算业务正确。

## 商家配置入口

### 首页装修 → 首页样式

- 既有：主视觉高度、顶栏主题浅底、首页保障内容（清空按原约定恢复默认）。新增独立保障条显示开关，修正原B端误写“清空即隐藏”的提示，避免保存后重新出现默认条目。
- 新增：C端背景底色、卡片底色、主/辅文字色；商品图比例（正方形、4:5、3:4）、桌面商品轨道3/3.5/4张。
- 新增：轮播和C端助手入口显示开关；关闭只影响展示，不撤销既有用户会话或改变API权限。
- 新增：商品标题下说明、页脚店铺介绍与联系说明、首页反馈区标题/副标题、详情页通用说明段落。
- 新增：助手欢迎语和最多6条快捷问题；昵称仍在店铺设置独立管理。
- 新增：实际包邮门槛、未满门槛运费，精确到分，0表示对应全店包邮；购物车、优惠券报价、订单创建均用同一店铺配置，优惠前商品金额判断包邮。已有订单金额不回算。
- 新增：发货及退换说明。它们是商家公开说明，不等于新增真实物流时效承诺或自动退款系统。知识工具带入当前店铺规则，不让通用知识片段的旧运费覆盖当前设置。

配置保存在独立 `shop_storefront_profiles` 表，正常启动自动建表，不给已有业务表增加列。B/C ShopOut 和 HomeOut.shop 返回同一份设置。嵌套PATCH只改传入字段，不把其他设置恢复默认。校验颜色、比例、列数、金额、字数和段落数量，不接收任意CSS或脚本。

### 首页装修 → 轮播图 / 商品栏目 / 反馈展示

- 轮播图：图片上传、标题、副标题、商品/栏目跳转、排序、启停。
- 商品栏目：标题、副标题、手动商品集合/销量来源、排序、启停；C端仅展示本店可见商品。
- 首页反馈卡：昵称、内容、评分、排序、启停由商家维护；它是运营展示，不应冒充不可篡改的真实订单评价。默认说明改为“店铺展示的买家反馈”。
- C端“用户评价”Tab来自真实Review记录，不能通过上述展示配置伪造或改写。

### 店铺设置

- 店名、公告、Logo、主题色、营业状态及10字以内的专属AI昵称。
- social_accounts已有API字段，但本轮未见B/C可见配置入口，不能算作已完成的界面配置项；它不是当前C页面已展示的部分。

### 商品管理

- SPU名称、分类、描述、封面、上下架、限购、挂载标签；补上已有API但原编辑表单遗漏的商品排序。
- SKU规格名、图片、售价、划线价、库存、上下架、最多12项可选参数；多SKU同属一个SPU。
- 商品详情不再给所有商品硬套“可手洗”“可回收包装”等固定描述，改用商家SPU说明和配置的通用段落。
- 修复清空SKU划线价无效：显式传null删除原价，省略字段保留原值。
- 修复商品卡跨SKU拼价：最低售价与卡片划线价必须来自同一个SKU，不能49元单只搭98元两只装原价造成虚假5折。
- 修复购物车图始终用SPU封面：优先使用所选SKU图，再回退封面；单据原有价格/名称/规格快照保持。

### 分类、商品标签、优惠券

- 分类与商品标签的新增、修改、排序、删除及挂载沿用现有管理页；标签名称/颜色同步到C端。字号、图标规范等平台级样式不开放任意脚本配置。
- 优惠券名称、满减门槛、金额、发行数量、有效期、启停由商家管理；C端领取和使用状态是用户业务数据，不是商家装饰项。
- 默认选券仍由已领券和服务端资格决定；本轮运费改造不改变单券、不抵运费及原子锁券规则。

## 不应开放给商家的字段

用户身份/权限、其他用户订单与地址、真实付款状态、历史订单金额、真实评价和销量、库存扣减结果、AI权限与工具安全校验不能作为“装修”任意修改。商品库存可以通过本店库存管理调整，但不能伪造已支付订单或销量。系统错误、安全提示、隐私隔离、支付演示标识保持平台控制。

本轮没有实现拖拽式任意页面编排、任意前端代码注入、按地区/重量运费、真实退款支付或知识库文档上传管理；不要把“主要内容可配”写成所有系统功能任意可配。

## 运行版本与证据

- 对8001执行只读HTTP审计（仅登录演示商家，未修改实际配置/商品/订单）：店铺基础字段、SPU上下架、共享SKU字段、首页、轮播、栏目、券条款通过。
- 当前运行进程仍缺新增storefront字段，并可复现SPU20跨SKU划线价问题；源代码已修复，但需要正常重启加载。报告 `backend/data/acceptance/bc-alignment-20261020.json` 如实保留失败项，不冒充已上线。
- `backend/scripts/audit_bc_alignment.py --report data/acceptance/bc-alignment-20261020.json` 是可重复的只读核对脚本（默认8001）。它不读/输出密钥、地址、工具结果或订单隐私。
- `backend/tests/test_storefront_alignment.py`：配置跨端/嵌套部分更新、颜色金额校验、角色/店铺隔离、运费报价购物车下单与旧快照、清空原价、SKU图、跨SKU拼价。
- `node backend/scripts/test_storefront_config.cjs`：后端与前端默认配置精确比较、CSS变量、运费边界；券选用与会话恢复脚本也复跑。
- 新表默认值不会覆盖已有装修；未对当前商家的实际样式做试写。运行旧接口时，B端新增表单禁用并明确提示重启，避免误报保存成功。

## 本轮验证结果

- 中间全量回归214项通过，183条既有短测试JWT警告，169.90秒。随后补充默认保障随新运费/发货/退换规则同步、金额显示不丢分、保障开关等后，定向联动与标签19项通过；不是新增214个真实云模型用例。
- Node前后端默认值、CSS变量/运费边界、优惠券自动选择、聊天恢复、JS语法及diff检查通过。
- 隔离UI服务用全新SQLite和内存Redis（端口18009，最多运行5分钟自动关闭），没有连接实际商家MySQL；通过B页面保存背景#efe4d4、4列、3:4商品图、隐藏轮播与保障、包邮200/运费15、页脚新文案，C端实际DOM/CSS分别匹配。截图 `docs/screenshots/storefront-config-isolated.png`。
- 隔离HTTP审计9组通过，报告 `backend/data/acceptance/bc-alignment-isolated-20261020.json`。隔离店无发行券，券条款一项只是空券样本；真实发行券字段对齐依据原8001读审计及已有优惠券测试。
- 当前8001读审计仍按实际情况保留新增配置未加载、SPU20卡片跨规格原价两个失败项，不能把隔离服务通过写成当前商家服务已经更新。源代码和配置表结构会在正常重启后生效，原商家数据不被测试设置覆盖。
