# 装修草稿、未保存预览与拖拽排序

## 使用流程

1. 首页装修的轮播、栏目、反馈、首页样式共用一份草稿。
2. 新增或编辑弹窗内可直接点「预览效果」，查看当前表单尚未应用的内容；返回编辑仍保留输入。
3. 「应用到草稿」以及列表的隐藏、删除、拖拽都不发布到买家端。
4. 顶部「预览」展示整份草稿；点击「保存并生效」才统一发布。预览窗口也可直接保存当前预览版本。
5. 「放弃草稿」恢复线上版本。草稿在当前标签页的sessionStorage按商家、店铺隔离，刷新可恢复；不是服务端跨设备草稿。

分类标签、商品标签、轮播图、商品栏目、反馈展示的所有上移/下移按钮均改为拖拽手柄。鼠标、触控通过Pointer Events排序，键盘聚焦手柄后可用方向键操作。分类与标签松开即保存；装修内容必须统一保存后才发布。

## 实现与边界

- GET `/api/v1/b/decoration` 返回装修内容及版本摘要。
- POST `/api/v1/b/decoration/preview` 校验本店作用域并生成只读预览数据，无配置写库、无发布。
- PUT `/api/v1/b/decoration` 校验版本、商品/栏目归属、链接目标，在一次事务中同步全部装修内容；新栏目临时负ID映射为真实ID，关联轮播同步转换。
- 版本不一致返回409，不覆盖其他页面的修改。新加载的页面若检测到缓存草稿与线上冲突，会提示并禁用保存，可先查看预览，再放弃过期草稿重新编辑。
- POST `/api/v1/b/sort/{kind}` 对完整列表一次事务排序，拒绝缺失、重复及其他店铺ID。
- 预览复用真实C端组件，在同源iframe内展示；通过来源、父窗口及随机nonce校验的postMessage传递预览数据，不传登录令牌。预览页面禁止业务API写请求及交互操作，不能加购、下单。
- 上传图片仍使用既有文件上传接口；上传文件本身会落盘，但未保存的装修引用不会出现在普通买家页面。
- 暂不提供商品详情/结算页的交互式预览或跨设备草稿同步。

## 验收

- 初轮全量225项通过；增加已有栏目关联替换后的最新快照测试，最终装修专项6项通过。前端草稿、配色、店铺配置、优惠券、聊天恢复与语法检查通过。
- 隔离浏览器：修改未应用表单背景为#efe4d4、隐藏轮播，直接预览可见修改；此时普通C接口仍返回#faf7f2、轮播开启。预览中保存后，后台摘要变为已保存版本。
- 隔离浏览器实际鼠标拖动轮播后仅草稿顺序改变，刷新恢复；分类实际鼠标拖动后保存且刷新保留。
- 两个实际服务端口已重启加载，MySQL、Redis就绪，B/C各9组只读数据对齐检查通过；未向实际店铺写入验收用装修或排序。
