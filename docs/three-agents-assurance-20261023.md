# 三个 Agent：首次使用与功能保障

本次目标：每个入口说明用途、前置条件、操作、输出、费用和失败后的下一步；已知错误必须有反例回归。范围是已登记能力，不将“有按钮”“发现接口”“固定回归通过”解释为无限制能力或全站所有分支覆盖。

## 业务 Agent：先拿到真实业务回答

1. 选择合成买家或合成商家。买家是购物小助手，商家是运营小助手，工具权限不同。
2. 可点“填入一个示例，先不运行”。只填文字，不自动发送或消耗模型额度。也可以自行提问。
3. 发送后等待完整回答；按需展开实际执行轨迹和业务证据。
4. 如需验证这条回答，在业务证据区填写预期并转为评测候选。候选还需审核启用、加入计划、实际运行；完成后到评测页选择来源。

注意：OP 对话使用合成副本，不是线上南枝商品目录；每段最多5轮，已有上下文后不能直接换身份，需开始新对话。商品/政策可以检索；订单和购物车必须按身份限制并实时 SQL 复核。商家配置指导不等于模型已经保存配置。

输出：客服式回答、相关商品、实际调用证据。模型或工具失败时明确失败，不补造成功。

## 功能测试 Agent：从需求到报告

1. 写“在哪一端、做什么、预期怎样”，确认环境；新手优先使用独立合成环境。
2. 点击“分析需求并匹配用例”，阅读匹配范围与未覆盖内容。判断可行不等于已经测试。
3. 创建计划，核对用例、环境、模型、预算与版本。等待模型规划完成后，再批准并启动。
4. 查看报告中的每条用例、实际步骤、预期与实际、错误、截图及清理状态。

还可以：在用例管理新增并审核用例，重跑已批准且仍有效的计划，按可比条件对比报告，查看 B/C/OP 能力目录。

自建声明式步骤目前支持商品列表、商品详情、查看购物车、加购、订单查询。其他业务动作需先登记受限执行工具；不接受任意代码、SQL、URL 或 shell。OP 治理与维护场景明确标为 OP，不伪装成 B/C 接口。

正式功能 Agent 必须实际通过模型工具编排执行；固定回归保留为显式诊断。实店固定执行档与隔离模型编排档分开，不取消实店保护来制造“全自动”效果。

## 评测 Agent：评测另外两个 Agent

1. 选择业务 Agent 或功能测试 Agent，再选择一份已结束运行。没有记录时可跳到功能测试先产出来源。
2. 生成程序核验。它只读取来源记录，不重新执行业务；历史评测可直接打开。
3. 按需补充模型评分，查看逐维度理由和证据。模型评分与程序核验分别保存。
4. 有审批权限者可填写人工复核；意见与程序或模型有分歧时保留分歧，不覆盖原始结论。

辅助功能：版本对比、同计划稳定性、隐藏集、缺陷基准、原始运行回放。

- 对比至少需要两份记录；目标、版本和来源不可比时明确说明。
- 稳定性需要真实重复运行；一次成功不叫稳定。
- 功能 Agent 评测会记录隐藏集独立对照。答案文件由管理员单独准备；缺文件为未启用，缺场景为证据不足，缺项不计通过。
- 隐藏集核对的是对应业务测试节点的实际执行结果，不是“某个测试执行过”的通用标记。它仍是固定回归对照，不冒充开放式模型盲测基准。
- 缺陷基准为4场景各执行正常/缺陷版，共8次执行。点击后先确认费用；最多32次模型调用、480000 tokens，可能等待数分钟；只使用合成记录。全局串行且定期续租，撤销执行权限或禁用账号后停止后续执行。

## 统一状态说明

- 通过：对应断言满足，不代表所有功能都覆盖。
- 失败：发现不符合预期的证据。测试 Agent 检出产品错误不等于测试 Agent 本身失败。
- 阻塞：模型、环境或执行链路未完成，不能按通过计算。
- 未观察/证据不足：缺少所需信息，不能猜结论。
- 未启用：需要的配置或答案文件尚未准备，不能把按钮存在当作能力已经可用。
- 清理成功：释放/归档测试资源，不等于用例通过。

## 已修复的保障缺口

- 业务来源 blocked/failed/cancelled 不会被通过的前置断言覆盖成程序核验通过。
- 隐藏集核对指定业务测试节点，要求全部答案与观察齐全；不允许部分答案将整集判通过。评测页实际展示该独立结论。
- 正式功能计划不能手动关闭模型执行器；联合计划中的功能部分同样需启用。
- 原有19个 active 场景补齐目录映射；自建功能用例按已批准动作映射到真实功能域，不再只能固定诊断。
- 缺陷基准贯通撤权、租约、并发与中断状态；长基准不再按短评分的超时窗口提前失效。
- 字面命中与语义候选合并、SKU去重；保留底层相关性阈值。语义服务失败但有确切字面事实时保留结果，没有事实时不猜无货。
- 评分时不重复传递静态目录源码，避免未请求模型就耗尽预算。完整源码仍在原始快照；目录摘要有明确 projection_note；行为会话、工具参数、执行结果不静默截断。真正过长的行为记录仍会明确阻塞。

## 第一次使用与边界保护

三个页面默认显示入门说明和步骤；“开始前 / 第一次怎么做 / 最终会得到 / 执行与费用”常驻。展开“全部功能说明、费用与失败处理”可查看进阶入口和故障恢复。提供用例管理、全部报告入口。

步骤卡只定位页面，不代替实际执行，不展示伪造的完成进度。只读账号明确提示缺少授权；缺少来源、答案、权限或前置状态时仍保留保护。

旧计划可能因功能目录、代码或模型指纹变化而失效；请重新生成计划、核对并批准。旧报告不改写、不拼接成新证据。对外助手回答不显示数据文件来源，OP 内部保留脱敏审计证据。

## 验收入口

- `backend/tests/test_agent_assurance.py`：状态、隐藏集、映射、自建动作、撤权、租约收尾、账户禁用和目录投影反例。
- `backend/scripts/audit_three_agents.py`：纯合成快速回归，不调用模型，不将其冒充 Agent 真实验收。
- `backend/scripts/check_op_report_ui.py --live-chain`：真实模型受理、标准计划执行、自建用例审核/规划/执行、独立评分、业务对话与新手浏览器交互。
- `backend/scripts/check_op_buttons.py`：OP 页面入口、治理按钮、维护工作区及确认/取消/错误提示；使用独立临时数据库。
- 全量 pytest、现有 Node 回归、JavaScript 语法与差异检查。

真实模型会有额度、网络和供应商故障，保障方式是明确失败、保留证据、守住权限预算并提供恢复路径，不承诺所有外部服务永不失败。本地验收不等于已部署线上。

## 本轮验证记录

- 全量后端回归检查点：543 passed、7 skipped；跳过项不计通过。
- 三类 Agent 真实模型端到端：73 项检查通过，包含标准功能执行、自建用例审核执行、独立评测模型评分及业务对话。
- 最终新手与报告浏览器检查：61 项通过，含桌面/移动布局、步骤定位、权限提示及需求输入防重复/旧结果清理。
- 新增 Node 流程与超时检查通过；超时覆盖 POST 模型任务与 GET 读取。请求超时明确提示先刷新历史，避免重复提交。
- 模型验收与写入均在独立合成数据环境执行；没有将诊断用例或缺失证据标为真实模型通过。本轮未提交或部署线上。
