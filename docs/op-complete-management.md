# OP 完整业务管理与三端对齐

本轮范围由用户确认：补齐现有业务，真实快递、第三方支付和资金退款另行接入。

## 入口

OP → 店铺管理 → 完整维护，或商品治理 → 完整编辑。
维护区始终显示 OP 身份、店铺名称/ID 和本次操作原因，可在窗口内操作或单独打开。
使用现有商家编辑器和同一套请求校验/服务，数据仍写入同一业务表；不复制商家令牌，不改 B/C 登录态。

## 覆盖范围

- 店铺：名称、公告、Logo、主题色、营业开关、助手昵称、社交账号与链接。
- 装修：背景/文字/卡片颜色、商品比例/列数、轮播高度和开关、运费门槛、发货退换文案、助手欢迎与快捷问题、详情模板和页脚。
- 内容：轮播图上传/跳转/启停/排序，栏目与商品关联/排序，反馈展示、保障文案；草稿、预览、整页保存及版本冲突检查。
- 商品：创建草稿、名称、描述、主图、分类、标签、限购、排序、上下架。
- SKU：创建、规格名、图片、价格、划线价及清空、库存、参数、排序、上下架。
- 分类与标签：新增/修改/删除/排序，标签背景/描边/文字颜色，以及商品关联。
- 优惠券：创建、门槛、金额、有效期、发行量、启停、领取/锁定/核销统计；领取与核销仍由原 C 端业务执行。
- 订单：按店铺管理、状态/明细/收货信息、原有发货/批量发货；OP 还可带原因取消待支付订单，复用原事务归还库存与优惠券。
- 客服：本店客户会话、历史消息、未读、关联订单和回复。
- 物流/售后：填写承运公司与单号、追加商家轨迹、受理/拒绝/完成售后，原状态机与跨店校验不变。
- 助手：同一店铺业务助手与提案预览/确认/取消；模型与工具日志沿用原有链路。
- 买家资料：从账号页按人分页查看地址、购物车、已领券、浏览历史、真实购买评价和订单。平台不代买家付款、领券、评价或确认收货。
- 平台治理：商品及单 SKU 禁售/解禁；账号禁用/恢复、密码重置；真实评价隐藏/恢复；独立封店/解封。

## 隔离与状态

`/api/v1/op/shops/{shop_id}/b/*` 和 `/support/*` 每次验证真实运营身份，再确定目标店铺的服务上下文。普通 B/C 令牌不能调用，资源 ID 仍经过原本的本店归属检查。运营身份不被提升为任意商户 JWT。

完整维护写请求必须提供操作原因。执行前持久化操作意图，执行后记录成功/失败；进程中断留下的 pending 表示结果待确认，而非承诺已完成。日志保留真实运营 ID 与店铺 ID，不记录请求正文、密码或令牌。

账号禁用和密码重置令已有令牌失效；恢复账号后须重新登录。撤销时间另存 BIGINT 微秒，避免 MySQL DATETIME 秒精度使同秒旧令牌继续有效。当前运营账号不能在该入口禁用或重置自己，避免误锁。

平台封店独立于商家营业开关。封店后公开商品、首页和可购状态关闭，新加购/下单/领券/支付受阻，商家不能自行重新营业。已付款订单仍能发货、查看物流和处理售后，平台也可继续维护配置。解封恢复原有营业设置，不自动修改商品上下架状态。

商品/SKU 解禁返回下架状态，须再次上架。真实评价隐藏只影响公开展示与评分统计，原文、原评分和购买关系保留。

OP 页面约15秒自动刷新；输入中、打开对话框或测试工作台时暂停，不打断编辑。数据仍通过查询获取，不声称实现 WebSocket 推送。订单/物流/售后维持先选店或搜索、默认近7天及20条分页。

## 验证

专项覆盖：B 路由契约均有 OP 作用域、非OP拒绝、跨店资源拒绝、完整商品/SKU字段及 C 对齐、分类/标签/内容/券、装修预览与冲突、平台封店、账号撤销与重置、物流售后、真实评价保留、买家资料权限、上传及排序、取消订单只归还一次。

发布前使用冻结快照运行后端全量及浏览器验收；生产只做已有记录的读取和界面核验，不写入测试订单/消息或修改真实商品。
