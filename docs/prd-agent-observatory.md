## 最新补充：模型角色与多用例报告

以 `agent-model-suitability.md` 的真实对照结论为准：业务及默认被测对象保留DeepSeek Flash，两个测试Agent规划默认GLM-4-Flash。旧文中“测试模型用于所有子进程”已由显式规划/目标角色分离取代，不把替代模型实验包装为实际业务Agent验收。

一份报告允许执行多条用例，批量同类10条/报告、手动计划最多20条；用例独立结果归入同一报告。Enter发送、Shift+Enter换行，导航顺序为业务Agent、功能测试Agent、评测Agent。

## 第二版：业务与评测解耦（2026-10-21）

此节取代下文第一版业务页“必须填写预期/先保存候选”的设计。业务页直接输入问题、选择合成买家/商家并查看回答、工具、知识来源与上下文；不出现测试用例选择、断言、通过率。独立调试接口只接受角色与1—5轮消息，服务端固定合成环境，真实模型执行；每次完整复现输入的多轮对话，先说明会重放历史，不能冒充持续存在的生产会话。

调试历史按当前OP账号隔离，Redis保留7天、最多10条；只有主动点击“转为评测候选”并填写预期后才调用原用例API，不自动审批或执行。调试只验证链路有真实模型调用，不替用户判断业务答案正确。

测试模型独立配置为GLM-4-Flash，外部密钥文件不入仓库。规划与助手评测/合成调试子进程使用此模型，B/C仍用DeepSeekFlash，Embedding不变。失败不得回退付费模型或规则后宣称真实评测通过；报告需保留实际模型和usage。功能状态验证仍由固定断言负责，默认先真实模型规划，不以模型意见替代库存/订单断言。确定性平台自测与正式模型验收分开标注。

## 目标与范围

在 OP「Agent 与测试中心」既有六页内升级三个 Agent 页面。让运营/研发看清真实执行过程，而不是仅阅读功能说明；B/C 不加载工作台资源，不获得测试权限。

第一版复用现有隔离执行、用例审批、请求证据和报告体系，不另造执行引擎，不接入生产用户聊天内容，不开放任意代码或 URL。历史报告只能显示当时采集的数据，缺失项明确标注，不补造事件、耗时或模型思维链。

## 三个页面的设计

### 业务 Agent：合成对话调试与业务执行回放

- 左栏：买家/商家角色、最多五轮消息、每轮预期文字；可选必需工具。必须有硬断言，不能只让模型宣称成功。
- 两步启动：先保存候选并展示原始定义；再明确「批准并运行」。依次复用用例审核、计划快照、计划批准、隔离任务创建，批准后不可悄悄变更输入。
- 调试为真实模型模式，仅合成身份和合成店铺，不调用实际商家账号。不自动加购、付款、退款或修改实际商品。
- 中栏：选择助手运行和用例，按请求顺序展示用户输入、实际意图、工具调用、知识引用、回答；不把最终答案倒推成真实规划。
- 右栏：点击步骤查看原始脱敏证据、商品结果、实际模型、上下文摘要模式及请求耗时。工具列表只有序号时标为「顺序记录，未采集独立耗时」。
- 模型配置沿用服务端，当前用户要求 Flash；前端不得选择 Pro 或发送供应商密钥。运行证据显示实际模型，不把当前配置冒充历史模型。

### 评测 Agent：从输入到断言的评测轨迹

- 复用现有计划编辑与审批，保留 fixed/model 两类规划入口。
- 工作台展示运行范围、模式、代码/用例快照和共享预算；按用例选择查看被测助手对话轨迹。
- 明确区分被测业务 Agent 的回答与评测 Agent 的判定。右栏展示每条断言的预期/实际/结果、可信事实与异常。
- 不用模型摘要覆盖硬失败；显示清理、阻塞、取消和预算未知，不合并助手与功能两组通过率。

### 功能测试 Agent：固定步骤与业务状态核验

- 复用既有功能计划和白名单执行器，不新增任意 shell、SQL、HTTP 目标。
- 中栏展示 pytest setup/call/teardown、真实接口请求、浏览器请求与错误证据；保留原报告中的截图入口。
- 右栏查看请求/响应、业务事实、断言、实际执行器与清理状态。接口通过不冒充浏览器通过，规则测试不冒充付费模型调用。

## 共用交互

- 页首三种视图：执行回放、能力配置、使用边界。配置第一版只读，编辑模型/提示词/长期记忆不在本批偷偷开放。
- 一次选择一条运行与一个用例；三栏为输入/任务、执行步骤、证据详情。窄屏改为上下排列。
- 刷新保留选择与未提交调试内容；切换账号清空本地状态。后台任务不通过前端定时器重新创建。
- 阅读只需 qa.view；保存调试候选需 qa.assistant.run；批准并启动还需 qa.approve。权限以现有 API 为准，隐藏按钮不能替代服务端校验。
- 保存候选不消耗模型；批准并运行会使用云端额度。最多20次模型HTTP调用、60000 tokens、600秒父任务预算，单隔离步骤仍遵循既有90秒上限；超限按原执行器停止。

## 验收与后续

- 三页均能从真实报告生成步骤，不同 Agent 的用例过滤正确；失败、403、缺轨迹、空结果有明确状态。
- 任意工具返回的 HTML/脚本只显示纯文本，不执行；无 auth token、密码或密钥进入工作台状态/导出。
- 模型调用次数只取 budget 证据，工具调用数不当作模型调用数；工具与知识没有单独计时不编造数字。
- 自定义调试完整保存、审核、建计划、启动、回放链路通过测试；重复点击使用幂等键，部分失败可重试已有计划而不是悄悄生成新执行。
- 后续批次再接入逐 span 埋点、逐节点实时状态、可审核提示词版本、受控记忆维护与生产脱敏采样。第一版不宣称已经实现这些能力。
