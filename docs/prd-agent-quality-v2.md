# B/C 功能测试与双对象 Agent 评测

## 用户目标

功能测试 Agent 以当前代码实现的 B/C 功能为事实依据，先读取功能契约，再调用对应已登记执行工具。评测 Agent 同时评估业务 Agent 与功能测试 Agent，分别保留任务结果、工具轨迹、完整会话，结合程序检查、独立模型评分和人工复核。

## 功能依据和执行

功能目录从 B/C、共享支持、商品提案和认证路由的 AST 生成，保留方法、路径、处理函数、权限依赖、输入模型和代码位置。按已审核业务域补充业务规则、页面入口、前置条件、独立验证目标和已登记场景映射。接口发现只证明入口存在，不证明全部业务分支已覆盖。目录摘要随代码变化，计划绑定不可变快照；旧计划不得套用新目录执行。

现有 pytest/API/UI 场景作为复合测试工具复用。模型必须读取真实功能与获批准工具，调用 execute_registered_case 后依据返回观察形成结果；不得生成代码、SQL、URL、接口或任意工具。复合场景内部采用确定性业务断言；模型不能覆盖断言、跳过失败或伪造成功。每份计划仍先批准，预算、取消、隔离和清理继续有效。模型不能调用的功能标记未覆盖；本期不是任意页面自主探索器。

## 双对象评测

业务 Agent：需求满足、事实依据、工具参数与权限、完整多轮会话、确认边界、容错、成本。

功能测试 Agent：目录依据、计划与执行一致性、实际工具轨迹、断言质量、失败归因、清理、缺陷发现及误报。历史固定执行记录可检查，但缺少模型执行轨迹时不可冒充自主 Agent 已验收。

程序评价只根据原始记录和可验证字段给出 passed/failed/not_observed。产品测试失败不等于测试 Agent 失败。独立模型按固定分维度量表评分，必须引用证据 ID；原始消息是待评数据而非指令，缺少证据不得补分。人工复核独立保存审核人、时间、结论、理由、乐观锁版本，不能改写原始断言。三种结果分别展示；未评分、被截断、缺证据、未复核都不能算全通过。

评测只接受服务端已结束运行，按 target 对结果筛选；联合运行不得混评。绑定原报告摘要、目录版本、量表版本、模型、实际预算与证据快照。人工结论与模型/程序冲突时提示复核，不由模型抹平。

## 隔离缺陷校准

提供受控购物车金额缺陷基准：相同真实测试协议分别检查正确实现与故意错误实现，记录检出与误报。仅在独立夹具内改变行为，不在真实商店注入故障。基准结果只证明对应探针能力，不能外推整个功能测试 Agent 的检出率。评测功能测试 Agent 应同时查看真实执行与该校准证据。

## OP 与验收

功能页新增 B/C 功能目录、源码依据、环境可执行场景与未覆盖项，可从功能生成受控计划。评测页新增对象选择、来源运行、程序评价、模型评分、人工复核、结果/轨迹/会话展开。模型评分显式发起并受预算限制，失败记 blocked。测试覆盖目录漂移、越界工具、模型无工具/伪通过、混对象、证据缺失、注入文本、模型非法引用、人工复核冲突和真实缺陷校准。
