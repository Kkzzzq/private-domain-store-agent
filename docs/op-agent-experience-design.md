# OP三个Agent展示改版

日期：2026-10-21。

## 信息架构

总览先展示三个Agent职责关系、当前已加载记录中的进行中任务、待审批计划和问题报告，再进入三个不同工作区。业务Agent为主要入口，功能测试和助手评测分别提供最近报告状态，不合并通过率。

业务工作区扩大对话与业务结果区域；实际执行轨迹置于可展开侧栏，步骤内容以可读文本显示，原始技术记录折叠。复用现有角色切换、历史对话与转评测候选，不改变对话执行行为。

功能测试与助手评测页把新建计划和计划审批移到工作区前面。左侧选择运行和场景，中间突出本场景结果，右侧保留所选步骤证据；技术轨迹、历史报告长列表和能力源码默认折叠。

功能测试中间显示检查目标、登记步骤、实际执行阶段和逐项核验。助手评测中间逐轮对照用户问题、业务助手实际回答及各断言预期/实际。复杂对象只显示可追溯摘要，完整值仍可展开；null不显示成0，缺失断言不显示通过。

## 实现边界

独立op-agent-experience.js/css作为展示层，通过op-quality两个兼容钩子接入。现有observatory存在时增强其三栏；没有observatory的旧页面保留原能力展示和执行入口。没有添加后端接口，不自动启动测试、批准计划、调用模型或改写报告；对话与测试记录仍由已有服务提供。

本地工作区存在尚未提交的observatory与业务调试模块、后端等并行工作。本次只提交新增展示层和精确接入钩子，不将其他工作混入发布。完整三工作区视觉验收针对当前本地OP，不能将其当作所有并行模块已经发布的证明。

## 验证

新增Node行为检查覆盖总览实际计数、评测输入回答对照、失败保留、缺失证据和文本安全；既有observatory与op-quality的Node回归通过。浏览器使用8000当前OP已有对话和报告只读验证，不发起新模型调用或测试运行。截图保存于backend/data/acceptance/op-redesign-*.png。

无独立耗时或进度事件的记录不生成动画进度或推测模型思考。完成状态与测试通过分开，清理成功与功能通过分开。
