# 全店知识覆盖与双端助手边界

## 需求方案

目标不是把数据库全部上传到一个公共向量库，而是让助手在允许的范围内完整理解本店数据和实际功能。所有检索结果只是候选；价格、库存、券资格、订单状态和购物车数量以实时业务查询为准。

### 人设与商品视图

- C端购物小助手：面向消费者，选购与比较、理解图片/规格、查看公开评价和活动、本人购物车/订单/物流/售后。商品只显示买家可见信息，不暴露草稿、经营指标、后台配置或其他买家的记录。
- B端运营小助手：面向商家，查本店全部SPU/SKU和状态、库存销量、订单履约、活动与装修配置，并指导实际后台操作。新增商品可以准备提案，任何保存/上架/退款/发券仍须在页面确认，不宣称已代操作。
- 两端都不在回复里附加来源、文件路径、源码、检索方式。内部证据在OP保留。会话与最近聊天按用户/店铺/角色分别存储，旧混合记录不自动带入。

### 数据覆盖与权限

1. SPU/SKU：名称、分类、说明、标签、规格、参数、图片关系全部可检索；价格/库存/销售状态实时读取。
2. 图片：SPU主图和每个SKU独立图分别保留product_id/sku_id/image_url/内容指纹。SKU无图明确标为继承SPU图，不能把其它SKU图片错配。图片像素使用多模态Embedding，不能把URL当作看懂图片。
3. 店铺配置：公告、公开保障、运费退换、启用的轮播/栏目/买家反馈；B端额外读取隐藏内容、主题样式、排序、分类与标签设置。
4. 优惠券：公开可领取规则以及当前买家已领券；B端可见本店全部券配置与发放状态。可用性须实时校验，不把向量里的旧规则当作优惠承诺。
5. 评论：本店公开评价与SKU关联，不暴露评价人的真实账号、订单号、手机或地址；商家维护的买家反馈与真实购买评价明确分开，不相互冒充。
6. 订单、物流、售后：C端限本人本店，B端限本店。语义文本只含脱敏的商品/规格/问题描述，具体单号和实时状态由SQL回填；地址、手机号、支付凭证不写向量。
7. 购物车：仅当前账号本店购物车，B端也不能查看其它买家私有购物车。数量、价格、失效状态实时读取。
8. 后台固定功能：商品/SPU/SKU创建与草稿、排序与图片、分类标签、优惠券、订单履约售后、首页装修预览发布、店铺设置与助手名称，依据现有界面编写商家专用操作手册，不向C端开放。

安全排除：密钥、口令、令牌、密码哈希、平台运营审计、其它店铺/用户的数据、未授权私信、收货地址和完整手机号不进入通用检索库。不能以“覆盖全面”为由绕过权限。

## 技术方案

- 商品文本沿用独立商品索引；图片采用独立多模态模型集合，与文本向量不混用。只处理受控站点图片和安全的公开HTTPS图片，禁止本机文件越界、私网URL与非图片文件。
- 新增白名单主题数据工具：服务端从Actor确定店铺/身份，不允许调用方传shop_id/user_id。先SQL按权限过滤，再生成脱敏文本并在数据库+店铺+角色+用户+主题隔离集合里召回。查询结束重新读取当前授权记录，已删除/变更的数据不能从旧索引复活。
- 商家固定手册独立于公共知识目录，不让C端知识检索间接命中后台教程。
- 文本与图片索引均增量更新、删除失效记录；模型切换使用独立集合。图像不可用要记为不可用，不伪称图片已经理解，不阻断已有文本搜索。
- 不为了Embedding丢弃实时查询：订单、购物车、券资格等动态数据由业务数据库负责；向量解决模糊描述匹配。
- 关键验收：跨店/跨用户/跨角色拒绝、两端会话隔离、图片与SKU对应、删除更新同步、实时价格库存复验、真实Embedding调用、B/C不同商品口吻和范围。

## 已实现与使用说明

- `query_store_data`按白名单读取配置、券、评价、本人购物车和授权订单/物流/售后。精确订单号只允许精确匹配，不将不存在的订单号模糊匹配成别人的或其它订单。
- `merchant_help`包含商品、分类、标签、券、订单、装修、店铺设置、经营概览、客户沟通、账号菜单10类功能，工具级禁止C端调用。手册是指引，不执行任何变更。
- `search_product_images`分析真实图片像素，采用独立多模态向量。站内图片校验目录范围、文件类型与4MB大小；公开HTTPS地址拒绝私网IP和不安全协议。SPU主图与SKU独立图分别保存，缺SKU图明确记录继承关系，命中独立SKU图时商品卡使用对应图。
- 图片API依照[阿里云多模态Embedding官方接口](https://www.alibabacloud.com/help/en/model-studio/multimodal-embedding-api-reference)实现，实测`qwen3-vl-embedding`图像/文本均返回2560维；图像与原文本模型集合严格分开。失败或无额度时明确不可用，不把URL或空结果伪装成已识图。
- 预热命令：在backend运行`.venv/Scripts/python.exe -m scripts.index_store_assistant --shop-code nanzhi --images`。仅写索引，不改业务表；公开上下文按店铺/角色共享，购物车、订单、售后、个人领券的索引按用户隔离并按本人查询同步，不批量上传所有买家私有数据。
- 索引随语义查询增量更新；精准查询和列表直接返回实时SQL，不为“用了Embedding”而强制增加模型调用。模型召回不代替权限、资格和业务状态校验。
- 隐藏评价不进入C端召回；商家维护的展示反馈不当作真实订单评价；订单向量不含地址、手机号或单号，售后原因只提取预定义问题类别用于索引，具体授权事实由SQL回填。
- B端与C端标题分别为“运营小助手”“购物小助手”，两端都不再追加来源、检索方式、调试提示。旧混合会话不自动迁移，避免把商家上下文带给买家；原Redis记录自然过期，不改商品订单。

## 本地验收记录

- 实际店C视图：33个在售SPU，89条SPU/SKU图片绑定；B视图：35个全状态SPU，93条图片绑定。均以真实多模态模型建立，未出现缺图；绑定数量不等于独立图片数量，演示数据存在不同SPU复用图片，向量相似不代表商品相同。
- 真实DeepSeek对话已验证：B讲优惠券设置步骤、C拒绝后台设置、C查本人购物车、B查SKU状态库存、C查可领券、C区分展示反馈与真实评价、B读取实际背景/运费/助手配置。保留在`backend/data/acceptance/store-personas-live.json`与`store-context-extra-live.json`。
- 图像实测及查询：`product-images-live.json`、`product-image-query-live.json`。前者为图片索引回执，后者为候选，不是人工确认全部图片内容和商品描述一致。
- 两端真实浏览器UI验证来源及内部提示不显示，采用隔离身份与模拟响应，仅验证展示，不冒充模型评测。脚本`backend/scripts/check_store_personas_ui.py`；回执`store-personas-ui.json`。
- 全量冻结首轮因未创建临时目录父目录出现20个fixture错误；修正验收环境后第二轮417通过、1项隔离复制图片失败，该项单独重跑通过。未放宽业务断言，也不把第二轮记录篡改成一次全绿。最新隐私/绑定专项与Node检查另保留通过记录。
