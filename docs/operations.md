# OP 平台运营台

访问 `/op.html`，使用专用运营账号登录。独立 `token_op` 不覆盖 B/C 登录。

功能：全平台经营概览、北京时间近7天下单趋势、店铺查询、商品搜索与禁售/解禁、订单与售后查询、优惠券发行领取监控、助手工具审计和运营操作记录。全部使用现有B/C数据库，列表每页20条，接口最多100条。

商品禁售沿用既有B端编辑限制和C端购买检查，解禁只恢复为下架，须商家再次上架。操作必须填写原因，审计与状态同事务持久保存，提交后清理C端目录缓存。运营台不披露订单收货信息、助手参数和密码。

运营权限使用独立 `platform_operators` 表，公开注册、统一B/C登录均不能自授权限。账号权限每次请求查库，撤销立即生效。已有账号的B/C身份和密码保持原样。

部署后，在 backend 目录使用同一Python环境和数据库配置授权专用账号：

```powershell
python -m app.operations_cli 专用账号名
python -m app.operations_cli 专用账号名 --revoke
```

授权命令随 backend/app 一起部署。不要为公开演示账号授予跨店运营权限。

金额口径为当前已支付/已发货/已完成订单应付金额，含运费，未扣实际退款；未接资金结算流水。售后保持既有商家处理流程，OP本期只查阅。低库存按启用且库存≤5的SKU统计，商品列表库存为全部规格库存合计。界面直接显示数据库记录，不造演示订单。
