# OP 平台运营台

访问 `/op.html`，使用专用运营账号登录。独立 `token_op` 不覆盖 B/C 登录。

功能：全平台经营概览、北京时间近7天下单趋势、平台账号管理、店铺管理、商品搜索与禁售/解禁、订单与售后查询、物流查询、优惠券发行领取监控、助手工具审计和运营操作记录。全部使用现有B/C数据库，列表每页20条，接口最多100条。

账号管理覆盖买家、商家和运营账号，展示关联小店、开店授权、运营权限、注销状态；可修改昵称，授权或撤销开店权限。开店权限复用 MerchantAccess，授予权限本身不自动建店，撤销权限后既有店铺和订单保留。账号可直接进入该买家的购买记录。平台权限不通过该编辑接口授予。

店铺管理展示店主账号、分享码、商品与订单计数，可修改名称、公告及当前营业状态，并进入该店商品或订单。营业状态是商家同样可修改的开关，不作为平台强制封店机制。商品详情展示同库SKU规格、价格、库存和状态。

订单、物流与售后页面默认不加载全平台订单，须先选店铺或搜索订单号、买家账号、物流单号。按店铺浏览默认最近7天，可选30/90/365天；关键词搜索查询历史记录（不叠加时间范围），仍受所选店铺限制。全部按20条分页。原 `/op/records/orders` 同样默认返回 needs_filter 空态。

订单详情展示下单时商品/规格/单价/数量快照、运费、优惠、订单应付金额、买家账号、收货人/电话/地址、运单和售后记录。仅运营权限可访问；收货信息不出现在列表。物流轨迹由商家填写，未接入快递公司实时查询。订单详情金额是应付金额，支付状态单独展示。

商品禁售沿用既有B端编辑限制和C端购买检查，解禁只恢复为下架，须商家再次上架。治理和管理写操作必须填写原因，并与审计同事务保存；商品和店铺修改后清理C端目录缓存。商品治理日志与平台账号/店铺管理日志分开查看。不披露助手参数、密码或密码哈希。

运营权限使用独立 `platform_operators` 表，公开注册、统一B/C登录均不能自授权限。账号权限每次请求查库，撤销立即生效。已有账号的B/C身份和密码保持原样。

部署后，在 backend 目录使用同一Python环境和数据库配置授权专用账号：

```powershell
python -m app.operations_cli 专用账号名
python -m app.operations_cli 专用账号名 --revoke
```

授权命令随 backend/app 一起部署。不要为公开演示账号授予跨店运营权限。

金额口径为当前已支付/已发货/已完成订单应付金额，含运费，未扣实际退款；未接资金结算流水。售后保持既有商家处理流程，OP本期只查阅。低库存按启用且库存≤5的SKU统计，商品列表库存为全部规格库存合计。界面直接显示数据库记录，不造演示订单。
