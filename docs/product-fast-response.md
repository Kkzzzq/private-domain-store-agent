# 商品问答快速响应

## 处理策略

- 商品价格、可售状态和 SKU 库存是实时业务事实，走 MySQL 和现有鉴权工具，不放进向量知识库后直接当库存答案。
- 商品介绍、材质说明、清洗方式、售后政策继续适用 RAG；未来可用向量检索召回“睡觉用的东西”等语义候选，但必须再回业务库核对商品状态、价格与库存。
- 本轮为明确问题增加**实时查询预览**：例如“抱枕有货吗”“马克杯多少钱”“SKU1库存”。在会话摘要和模型推理前，先通过原有 guard 执行本店查询，把真实结果推送给用户，随后仍由真实模型执行原工具流程并形成最终回答。
- 这是“业务事实先到、AI解释后到”，不是无模型规则回答冒充 LLM，也不是声称完整答案已秒回。最终答案生成时替换预览，预览明确标明下单时需再次校验。
- 模糊指代、多条件推荐、价格比较、政策与订单混合问题不猜测；查不到或工具失败不发送预览，继续原链路。只在有流式回调时工作，旧 JSON 接口不额外查一遍。
- 查询只读，继续使用服务端当前用户和店铺上下文，传入其他店铺 SKU 不会泄露数据。前端不缓存用户订单或最终库存答案。

## 界面

买家气泡按内容自适应宽度并靠左，自己的消息靠右，不再由 flex 默认拉伸而在等待文字右侧留一截。等待文案仍使用店铺固定昵称。预览到达后会安全渲染查询结果，并保留等待提示直到模型完成；不会被心跳覆盖回纯等待文字。

## 激活与范围

前端刷新即可使用气泡样式修正。后端预览事件是新代码，必须正常重启后端加载，当前无热重载；此前自动停止命令被工具策略拒绝，未绕过限制。不能把纯代码测试或直接数据库计时冒称当前8000进程已发出新预览事件。

`check_chat_progress.py` 已增加 first_preview_ms 记录，后端正常重启后可用于测量真实网络首条业务结果耗时。完整云模型耗时仍受推理与服务排队影响；SQL预览不能消除最终模型等待。
