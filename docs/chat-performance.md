# 助手响应优化与实测

日期：2026-10-19。本轮保持智谱 GLM-5.3-Flash、真实 MySQL/Redis 与原工具权限校验，不改成静态答案或规则假装模型。

## 改动

- 买家、商家新增 POST `/chat/stream`（买家仍带原店铺路径），使用 NDJSON 实时推送接收、会话、模型处理、业务工具、保存、最终结果/错误。不是大模型逐 token 输出，不输出内部推理内容。旧 JSON 接口保留。
- 页面不再只停留在“正在查”。每个阶段由后端实际执行位置触发；10 秒无新阶段时发送心跳，仅提示仍在处理及已等待时间，不伪造百分比。
- 云模型 HTTP 请求使用有连接数量限制的持久客户端，复用同一进程中的连接，减少工具循环反复建连开销；保留密钥读取、额度切换及异常处理。
- “我要睡觉用的东西”等用途请求识别为推荐，只开放阶段所需工具；原先泛意图会开放全部允许工具。政策、订单、库存的明确意图仍优先。
- 提示模型复用工具已返回的 SKU 库存，避免对同一结果逐个重复查库存；仍由工具实时查询数据库，不缓存库存或跨用户最终答案。
- 流式工作线程有独立数据库会话和用户上下文，最多八个并发执行；角色鉴权在开始响应前执行。流建立后错误用 error 事件返回，前端不得当成功结果。内部异常不返回密钥或数据库连接信息。
- 断开后在下一个阶段边界停止后续工作；已发出的同步云 HTTP 请求不能瞬间撤回，可能持续到返回或超时。现有单次云请求超时、工具循环上限仍保留，本轮没有新增严格的整轮总时限。

## 真实本机演示 API 结果

- 问“抱枕有货吗”：首个阶段反馈 49ms，完整结果 12,276ms；模型两轮分别 4,311ms、7,194ms，商品工具 234ms；真实 llm 模式、search_products、无纠正重试。
- 问“我要睡觉用的东西”：首反馈 6ms，完整结果 28,256ms；真实 get_store_catalog 11ms、recommend_products 10ms，三轮模型合计约 28.2 秒，无纠正重试。说明用途推荐的主要耗时仍在模型，不能称为秒级完整回答。
- 同问的旧泛意图新会话曾 18.29 秒返回澄清；当前新链路增加了真实商品概览与筛选，任务不同，不能用这两次数字宣称回答速度提升。
- 独立进程试测 GLM-4.7-Flash 同一库存问题约 79.79 秒，首轮模型约 76.44 秒。只是单样本，不证明模型长期性能；没有据此替换当前首选模型。
- 两份流式报告位于忽略目录 `backend/data/acceptance/chat-progress-inventory.json` 与 `chat-progress-purpose.json`，只保存阶段/耗时/工具名称等，不保存登录令牌、工具业务结果或模型推理文本。报告是真实依赖样本，不是稳定 SLA 或多轮压测统计。

## 验证与复跑

- 初轮完整回归 173 项通过；追加真实工具循环阶段、流式业务错误与跨用户订单隔离测试后，定向流式套件 13 项通过。既有短测试 JWT 密钥警告不代表生产配置已验收。
- 原云协议/推荐/严格依赖定向 72 项通过；前端 UTF-8 跨分片 NDJSON 解析通过，三份 JavaScript 语法检查通过。未宣称完成浏览器视觉自动化。
- `cd backend; .venv\Scripts\python.exe scripts\check_chat_progress.py --report data/acceptance/chat-progress-inventory.json` 可复跑演示 alice 账号的库存问题；`--message` 可换问题。脚本只请求回环地址 8000，使用既有演示账号，勿当生产测试脚本。

## 仍需关注

运行状态：核心阶段流、路由和连接复用已在本机 8000 演示进程加载并实测。随后追加的“断开后阶段取消”和 worker 外层异常保护已通过定向测试，但最后一次重启命令被工具策略拒绝，未绕过限制；这两处防护需下次正常重启后端生效。现有演示 API 继续返回 HTTP 200。

连接复用和收窄工具集减少可避免的开销，阶段流让用户立即知道在做什么；无法消除模型服务排队与推理。若还需压低完整答案耗时，下一步应以同题多样本比较候选模型的耗时和工具正确率，再考虑分流；不能仅凭模型名的 Flash 就认定更快。真正逐 token 回答与完整请求总时限不在本轮已完成范围。
