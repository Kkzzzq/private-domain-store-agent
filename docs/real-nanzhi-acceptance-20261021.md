# 线上南枝小店实店验收

目标由用户明确指定为 `https://shop.kkzzzq.cyou`；本机数据库不造数。线上分享码 nanzhi，对应现有店铺「南枝手作」。

## 数据

`nanzhi-demo-20261021` 批次已经提交至线上数据库：8 件商品、24 个 SKU、6 位演示买家、12 笔订单、地址、购物车、分类、标签、规格参数、优惠券与领取记录、物流、售后、评价、双向客服消息，以及首页横幅、栏目和展示评价。演示已付款状态不代表实际收款；演示物流未请求快递供应商。首次执行在提交后刷新缓存时误传参数，数据未回滚；已清缓存并修正脚本为零参数调用。重复执行只校验批次完整性，不重复创建。

## 执行档

服务器显式启用 `QA_REAL_SHOP_ENABLED=true` 后，三个类型均只使用 `real-nanzhi`：12 条接口 RF01–RF12、6 条真实业务 Agent RA01–RA06、8 条真实 UI RE01–RE08。目录、中文步骤和预期在 `real_cases.py`；执行器为 `real_runner.py`。

原 91 条隔离诊断及其历史报告保留。它们不会接入真实数据库或冒名记为实店通过；线上当前实店目录显示上述 26 条用例。全店冻结、停用既有真实账号等旧诊断不在这 26 条中，不声称已经完成这些破坏性操作的实店验证。

固定步骤与数据库硬断言通过既有计划、批准、worker、结果表和报告展示运行。接口与 UI 使用固定执行器；Agent 请求实际线上业务助手且强制 `mode=llm`，规则回退判失败。此执行档不调用测试规划模型，不混称模型规划验收。单份 Agent 计划只运行一条，因为远端聊天 API 无法提供模型服务 usage；调用和 Token 预算按整份保守占用，报告明确显示估算，真实 HTTP、工具审计和断言另存。

## 写入范围及中断恢复

每条用例创建不可猜测标记的专用买家，涉及商品的用例创建专用商品。只操作本轮记录，不改原商品、原账号密码及店铺经营设置。结束后下架本轮商品、关闭本轮券、取消本轮未付款订单、清本轮购物车和撤销临时令牌；保留订单、售后、消息、评价及平台审计。

子进程中断时，父 worker 根据独立台账归档；worker 重启后也会检查超过十分钟的遗留台账。恢复操作按不可猜测用户名、商品描述和批次标记核对归属，不接受任意商品 ID。

## 验证记录

- 造数后真实线上只读检查 443 项通过，后台 43 件商品、买家可见 38 件。
- 发布快照全量 385 项通过；包含真实适配器与既有业务 HTTP 路由的事务、权限、取消库存、物流、售后及消息测试。
- 第一轮线上实测 12 条接口全部通过；Agent 5/6 通过，UI 5/8 通过。失败记录原样保留。
- Agent 售后知识检索失败定位为服务账号不可读取 `filelock` 包；修复权限并重载服务后，RA05 复验通过。部署接收器补充主虚拟环境组读取权限，避免再次发生。
- UI 三项失败定位为测试同时注入了不同账号的 B/C 令牌，统一会话正确地阻止了混用。改为每条用例只注入对应身份，RE01、RE05、RE06 在真实站点复验全部通过。

最终上线状态和经正式页面/worker执行的报告编号在完成后增补；以上预验收不冒充尚未执行的正式任务。
