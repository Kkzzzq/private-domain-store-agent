## 报告行为

报告按北京时间命名 `YYYY-MM-DD HH:mm 测试报告`，按日期过滤对应 UTC 时间窗口。列表仅展示结束的真实运行，最多 100 份；详情保留报告编号区分同一分钟多次运行。每条用例展示中文名称、步骤、预期、实际证据；成功绿色，失败/阻塞红色；截图携带哈希并通过 OP 鉴权接口访问。新计划冻结文档快照，后续文案修改不改写旧报告。

默认保留 7 天报告与孤立截图，计划和活动任务保留。测试资料、图片上传和静态资源均位于每个子进程独立临时目录，不写业务上传目录。

## 持续运行与部署

新增独立 QA Python 环境、浏览器运行时与 `private-store-quality.service`，部署同步 `backend/tests` 与 `backend/scripts`。准备依赖时商城继续运行；切换前停止旧 worker，健康检查通过后启动匹配新代码的 worker。服务采用 storeapp、独立临时目录及 CPU/内存限制，QA 文件写权限仅 backend/data。

本机可重复执行：

```powershell
cd backend
.venv/Scripts/python.exe -m scripts.run_quality_acceptance --kind functional --report data/acceptance/functional.json
.venv/Scripts/python.exe -m scripts.run_quality_acceptance --kind assistant --report data/acceptance/assistant.json
```

脚本只接受本机报告数据库和既有 OP 身份，不自动创建管理员；业务写测试交给隔离子进程。线上使用已配置的模型服务，不把本机 DeepSeek 结果表述为线上其他供应商也已通过。
