# 店铺专属 AI 与回答渲染

## 昵称

每家店独立存入 `shop_assistant_profiles` 表，主键为店铺 ID，不更改旧业务表列。未定义时初始化调用真实聊天模型，根据店名取昵称；有效结果仅接受“小＋一个中文字”，共两个字。模型失败或格式异常时使用店名生成两字兜底并持久保存，不因刷新、重启或店名变化自动重新取名。旧版较长自动昵称按本次需求一次性缩为“小＋末字”，不改商家自定义名称。

商家在“店铺设置 → 专属 AI 昵称”自定义，1–10 个中文、字母、数字、间隔点、下划线或短横线，无空格，输入框和 API 均限制10字。复用本店商家权限，买家不能修改。AI 系统提示同步固定昵称，前台标题也展示昵称。

2026-10-19 已在本机 `private_store_demo` 创建新资料表并用真实模型为南枝手作生成小南枝，本次按两字需求将其缩为 **小枝**，记录来源 `ai`。商家未修改前保持不变。没有复制密钥到数据库或前端。

运行中的旧后端没有自动热重载：本轮昵称接口/修改逻辑须正常重启后端后生效；此前重启指令已被工具策略阻止，本轮未绕过。前端刷新可立即使用店名兜底文案和回答渲染；旧接口未返回 assistant_name 时，后台保存会明确提示昵称尚未生效，不假报昵称保存成功。正常重启会自动建表并初始化未命名店铺，已有资料不会再请求模型。

## 等待与回答

- 双端等待文案固定为“{昵称}正在理解并且为您提供最优方案”，不再把模型阶段、心跳提示直接替换到气泡里。
- 仍保留后端真实阶段事件和心跳，展示文案不代表已经完成推荐，也不承诺全局数学最优。
- 支持段落、换行、加粗、编号/无序列表、标题、行内代码、代码块和 HTTP(S) 链接的安全 Markdown 子集；不是完整 CommonMark 引擎。
- 全部通过 DOM 节点与 textContent 构造，不把回答赋给 innerHTML；原始 HTML 当文本，javascript/data 链接不生成可点击链接。用户输入保持纯文本，重新打开对话也按相同方式渲染助手历史。
- 当前仅对换行分隔的列表识别列表结构，不擅自重写数字金额或将任意句内编号拆开。模型应输出正常 Markdown 换行。
